# Родово — семейный архив

Веб-приложение для ведения семейного дерева: люди и родственные связи, биографии, фотографии и голосовые записи, истории и журнал изменений. Каждая семья — отдельное пространство с ролями участников.

## Стек

- **Next.js 15** (App Router) + **React 19** + **TypeScript**
- **PostgreSQL** + **Prisma 6** (ORM, версионируемые миграции)
- **Redis** (опционально) — общий стор для ограничения частоты запросов при нескольких инстансах
- Собственная сессионная аутентификация (scrypt + httpOnly-cookie)
- Медиафайлы пока хранятся на диске в каталоге `storage/` (планируется вынести в объектное хранилище)

## Требования

- Node.js 20.9+ (проверенная локальная версия — 22.19.0)
- Docker (для локальной базы PostgreSQL и Redis)
- npm

## Быстрый старт

```bash
# 1. Установить зависимости
npm ci

# 2. Создать файл окружения (Windows CMD: copy .env.example .env)
cp .env.example .env

# 3. Поднять базу PostgreSQL (и Redis) в Docker
npm run db:up

# 4. Применить миграции и наполнить демо-данными
npm run db:migrate        # создаст/применит миграции
npm run prisma:seed       # демо-семья Ахмедовых (по желанию)

# 5. Запустить дев-сервер
npm run dev
```

Приложение поднимется на http://localhost:3000, база — на `localhost:5432`.

## Переменные окружения

| Переменная            | Назначение                                                   | Пример                                                        |
| --------------------- | ------------------------------------------------------------ | ------------------------------------------------------------ |
| `DATABASE_URL`        | Строка подключения Prisma к PostgreSQL                       | `postgresql://rodovo:rodovo@localhost:5432/rodovo?schema=public` |
| `REDIS_URL`           | (опц.) Redis для rate-limiting при нескольких инстансах      | `redis://localhost:6379`                                     |
| `TRUST_PROXY_HEADERS` | Доверять `x-forwarded-for` для rate-limiting (за прокси)     | `true`                                                       |

Файл `.env` в репозиторий не коммитится (см. `.gitignore`). Шаблон — в `.env.example`.

## База данных и миграции

Схема лежит в `prisma/schema.prisma` (провайдер — `postgresql`). История миграций
хранится в `prisma/migrations/` и коммитится в репозиторий.

```bash
# Создать новую миграцию после изменения схемы
npm run db:migrate -- --name описание_изменения

# Применить существующие миграции (например, на проде)
npm run db:deploy
```

Docker-инфраструктура описана в `docker-compose.yml` (Postgres + Redis с
именованными томами; `docker compose down -v` удаляет данные).

### Продакшн-заметки

- Для serverless-хостинга (например, Vercel) с Postgres используйте пул
  подключений (PgBouncer / Neon pooling / Prisma Accelerate) и, при
  необходимости, отдельный `directUrl` для миграций.
- При запуске нескольких инстансов приложения задайте `REDIS_URL`, чтобы
  ограничение частоты запросов было общим. Без него лимитер работает в памяти
  каждого инстанса.
- Медиа для масштабирования вынесите в объектное хранилище (S3 / Cloudflare R2).

## Структура проекта

```
app/                 — маршруты и API (App Router)
  api/               — REST-эндпоинты (auth, families, people, media)
components/          — клиентские и серверные компоненты UI
lib/                 — бизнес-логика, доступ к данным, аутентификация
  auth.ts            — сессии, пароли, проверка ролей
  family-repository.ts — операции над семьёй/людьми/медиа (в транзакциях)
  family-media-repository.ts — резервы квот и жизненный цикл медиа
  family-logic.ts    — чистая логика дерева и связей
  family-utils.ts    — раскладка дерева для UI
  media-storage.ts   — валидация и хранение загрузок
  rate-limit.ts      — ограничение частоты (in-memory или Redis)
prisma/              — схема, миграции, сиды
tests/               — юнит-тесты (node:test через tsx)
docker-compose.yml   — локальные PostgreSQL и Redis
```

## Безопасность

- Пароли хешируются scrypt со случайной солью; сравнение — `timingSafeEqual`.
- Сессии — в httpOnly/SameSite=Lax cookie, токен хранится в БД как SHA-256-хеш; просроченные сессии подчищаются.
- Доступ к данным семьи проверяется по ролям (`owner/admin/editor/member/guest`).
- Загрузки проверяются по сигнатуре файла, ограничены по размеру; пути защищены от traversal.
- На вход/регистрацию действует ограничение частоты запросов.
- Security-заголовки (CSP и др.) настроены в `next.config.ts`.

Подтверждение почты, принятие приглашений, смена/сброс пароля и отзыв сессий
описаны в [правилах безопасности аккаунтов](docs/account-security.ru.md).
Внешняя доставка писем пока не подключена; миграции новых этапов требуют
отдельной проверки и согласованного применения. Старые адреса не считаются
подтверждёнными автоматически, существующие членства сохраняются.

Постоянный том, квоты, состояния загрузок и выдача аудио по диапазонам описаны
в [правилах хранения медиа](docs/media-storage.ru.md). Офлайн-проверка копии БД
и оригиналов: [резервное копирование и восстановление](docs/backup-recovery.ru.md).
Миграция медиа подготовлена, но не применена; реальная тренировка восстановления
на отдельном PostgreSQL-стенде ещё требуется.

CI, проверки состояния сервера и порядок выпуска:
[операционный регламент](docs/release-operations.ru.md).
Измеренные UI-проверки и оставшаяся матрица:
[приёмка QA-01](docs/qa-acceptance.ru.md).
