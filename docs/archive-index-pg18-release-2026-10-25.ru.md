# Проверка release индекса на PostgreSQL 18.6

25.10.2026. Проверка завершена на отдельном локальном PostgreSQL **18.6**
(`server_version_num=180006`), Windows x64, Prisma CLI **6.8.2**, 421 000
синтетических записей. Рабочая БД и почта в этой задаче не подключались.

После упаковки ZIP извлечён в новый каталог: совпали хеши всех 26 файлов и самого

Нужны проверенные версии из manifest и lockfile, SHA которого записан в отчёте упаковки.

## Согласование исторических checksum

Все восемь исторических SQL в обоих наборах точно совпадают по SHA-256 с ранее
сохранённой read-only историей рабочей БД. Для подготовки новая рабочая диагностика
не выполнялась. Базовые checksum включены в `baseline-checksums.json`, без секретов.

Только в копиях `20260928000000_direct_sibling_relationship/migration.sql`
CRLF заменён на LF. Получился ожидаемый рабочий checksum:
`efdb04e0d3fab50f81d3370c45a841be3a7a29a1c1ba1ea746680e6bdb3c4bfe`.
Другие SQL скопированы побайтно. Исходный файл в `prisma/migrations` не менялся.
CREATE и DROP сохранили ранее проверенные checksum:

```text
CREATE a84eb87e424bea2cc6d9a55e896c7b5c5bec6d475dc905cbb9a6121c4e9ec97d
DROP   86f1956386e23ec112157dbcb0f8ceae0116c7aa6c8635986a7fd1c6e097d502
```

`.gitattributes` внутри артефакта отключает преобразование строк. История рабочей
БД не исправлялась и не переписывалась. После фактического отката история следующего
release должна включать новую DROP-миграцию; это описано в README.

| CREATE при блокировке, lock 3s / statement 60s | 55P03, индекс отсутствует | 4,548 |
| CREATE при блокировке, lock 3s / statement 1s | 57014, индекс отсутствует | 2,446 |
| CREATE без блокировки, lock 3s / statement 60s | правильный индекс, valid/ready | 3,934 |
| DROP при блокировке, lock 3s / statement 60s | 55P03, индекс сохранён | 4,535 |
| DROP при блокировке, lock 3s / statement 1s | 57014, индекс сохранён | 2,297 |
| DROP без блокировки, lock 3s / statement 60s | индекс удалён | 2,579 |
| Выполнение pg_sleep(5), statement 1s | 57014 во время выполнения | 2,529 |

Время CLI включает запуск процесса, подключение и работу с историей миграций;
это не чистое время DDL и не прогноз длительности рабочего окна.

Внутри отдельной probe-миграции подтверждены `lock_timeout=3s` и
`statement_timeout=60s`, переданные через URL `options`. `PGOPTIONS` был пустым;
глобальные настройки и роли не менялись. Полное истечение 60 секунд не ожидалось:
значение проверено внутри мигратора, механизм отмены — с лимитом 1s.
Внешний watchdog runner — 30s; это дополнительная лабораторная защита.

После каждой ошибки проверен каталог и штатно вызван `resolve --rolled-back`.
После успешного CREATE и DROP проверены checksum всех активных записей истории,
`migrate status`, отсутствие schema diff и no-op повторного deploy.
После DROP fingerprint всех полей Person и количество 421 000 строк совпали с
исходными. Исходная CREATE остаётся в истории, откат записан новой forward-миграцией.
Probe-миграции созданы только в лаборатории и не включены в release ZIP.

## Изоляция и проверки проекта

Использован новый кластер с ownership marker, только loopback и нестандартный порт.
Runner до первой мутации проверил URL, маркер, пустоту БД, точную версию 180006,
последовательность файлов и базовые checksum. Prisma запускался из отдельного
каталога со своим `package.json`, явным тестовым URL и без загрузки проектного `.env`.
Код приложения и почтовые модули не запускались.

Переносимые бинарные файлы получены с [официальной страницы EDB](https://www.enterprisedb.com/download-postgresql-binaries).
Архив `postgresql-18.6-5-windows-x64-binaries.zip` сверён с SHA-256 поставщика:
`e2246ba91d22345bc3d017586c09ede52d9df180b1eeb480f050445f1cad84e2`.
Системная служба и новые пакеты проекта не устанавливались.

Проверки: **769/769** unit-тестов, TypeScript и ESLint — успешно.
Независимое ревью проверило guards, manifest, baseline и изоляцию наборов.
Production build и UI-тесты не повторялись: приложение не менялось.
Сохранность 19 ранее изменённых tracked-файлов подтверждена сравнением SHA-256;
исходная схема и миграции сохранены. Тестовый сервер остановлен, listener освобождён.
Лабораторные файлы оставлены в `tmp/index-pg18-lab-1792920208076`, не являются backup.

## Что остаётся перед рабочим применением

Проверка устраняет различие major/minor PostgreSQL и расхождение checksum release.
Она не воспроизводит Neon на Linux ARM64, рабочие квоты, нагрузку, backup и SLA.
Перед будущим запуском нужны свежая read-only сверка истории/схемы/блокировок,
резервная копия с восстановлением, согласованное окно и отдельное разрешение по
[плану применения](archive-index-production-plan.ru.md). Использовать прямой Neon
endpoint: ранее pooled endpoint отклонил startup-параметры таймаутов.
Рабочий запуск текущей задачей не разрешён и не выполнялся.
