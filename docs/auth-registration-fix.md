# Исправление регистрации и переходов авторизации

## Причина

При открытии сайта на `http://127.0.0.1:3000` Next.js 15 нормализует URL внутри Route Handler до `http://localhost:3000`. Браузер сохраняет исходный `Origin`. Прежнее сравнение этих строк отклоняло собственную форму как запрос с чужого сайта. Абсолютные редиректы также заменяли адрес браузера на `localhost`.

## Изменения

- `lib/request-origin.ts` восстанавливает исходный локальный адрес по `Host` только для уже локального URL и точных адресов `localhost`, `127.0.0.1`, `[::1]` с тем же портом. Схема берётся из URL. Произвольные хосты и forwarded-заголовки не используются.
- Общая проверка `assertSameOrigin` сравнивает `Origin` с этим адресом. Различия хоста, схемы и порта по-прежнему отклоняются.
- Регистрация, вход и выход сохраняют адрес сайта в редиректах.
- Ошибка входа сохраняет безопасный внутренний `redirectTo`; внешние и некорректные пути заменяются на `/families`.
- Переход к созданию семьи без входа сохраняет целевую страницу. Ссылка возврата на этой странице ведёт к списку семей, а не по кругу через регистрацию.

## Проверки

- `npm test`: 82 теста прошли, включая 20 новых проверок Origin, редиректов и регистрации.
- Успешная регистрация проверена через настоящий обработчик с изолированными заглушками Prisma и cookie: нормализация данных, хеш пароля, сессия, срок действия и параметры cookie в test/production.
- TypeScript и ESLint проходят.
- `npm run build` прошёл; production-сервер перезапущен на `127.0.0.1:3000`.
- На живом сервере запрос со своим Origin доходит до проверки полей, чужой Origin отклоняется, ошибка входа сохраняет целевой путь.
- В браузере отправка заведомо некорректной формы показывает ошибку поля и остаётся на `127.0.0.1`; создание семьи без входа открывает логин с целевым путём.
- В production повторно проверены отправка формы и ссылки регистрация → вход → регистрация, ошибок консоли нет. Главная, демо, вход и регистрация возвращают 200; закрытые страницы перенаправляют на вход. API создания семьи отвечает 401 без авторизации для своего Origin и 403 для чужого.
- Реальные аккаунты не создавались. Рабочая БД и пользовательские сессии не изменялись; интеграционные тесты против рабочей БД не запускались.
