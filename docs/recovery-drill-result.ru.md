# Тренировка восстановления БД и файлов

Прогон: 30 сентября 2026. Отчёт завершён 1 октября 2026.
Статус: синтетическая тренировка БД + media + HTTP успешно завершена.

## Объём

Отдельный контейнер PostgreSQL 16.15, две разные тестовые базы: источник
`rodovo_ci_test` и пустая цель `rodovo_recovery_test`. Доступ с хоста только
через loopback-порт 55432; файлы PostgreSQL находятся в tmpfs. Данные семьи,
пользователи и медиа полностью синтетические. Рабочие данные не читаются.

Порядок: миграции источника → создание синтетических записей и файлов →
фиксация снимка без сторонних writers → pg_dump custom → упаковка готового
дампа и media с manifest/SHA-256 → проверка пакета → отдельная файловая копия →
pg_restore в пустую целевую БД → сверка → HTTP-проверка приложения.

## Критерии

- pg_dump и pg_restore завершаются успешно, версии совместимы с сервером.
- Восстановление выполняется одной транзакцией, без --clean/--create/reset.
- Строки, история миграций и контрольные количества совпадают со снимком.
- Для всех файлов совпадают SHA-256; для ready-медиа также ключи и размеры БД.
- Архивные люди, удалённые истории и все состояния медиа сохраняются.
- Приложение подключено только к восстановленной БД и отдельному storage;
  вход, доступ к семье, фото и Range-аудио проверяются через HTTP.
- Собственный сервер, контейнер и временные каталоги очищаются после прогона.

## Ограничения

Это проверка небольшого синтетического набора. Она не подтверждает скорость
восстановления production-объёма, RPO по расписанию, хранение на независимом
носителе, шифрование, ACL, доставку оповещений или аварийное восстановление
всего кластера. HTTP-проверка не заменяет браузерную приёмку и screen reader.
Старые/новые схемы проверялись отдельно в `legacy-upgrade-acceptance.ru.md`.

## Результат

`npm run test:recovery`: PASS, exit 0; `tmp/recovery-drill-final.log`.
Сравнены 14 таблиц приложения и история миграций — всего 15 таблиц.
Восстановлены 3 человека (1 архивный), 2 связи, 2 истории (1 удалённая),
5 медиа: ready=2, pending=1, deleting=1, failed=1. Пакет содержит 7 файлов
(дамп, 5 оригиналов, 1 partial), 46 525 байт. Потерь строк и файлов нет.

| Сверка | 77 мс |

Настоящий HTTP-вход, открытие семьи, байты фото и Range-аудио прошли.
Фото без авторизации возвращает 401; pending/deleting/failed — 404 даже
после входа. Исходная сессия после восстановления также действительна.
Сравнение снимков выполнено до входа, создающего новую сессию.

Повторный запуск на непустых БД отклонён до изменений. Scoped backup/guard
тесты: 14/14 PASS, TypeScript и ESLint PASS; независимый DB/code/TS review
APPROVE. Контейнер удалён после сверки ID/метки, временные каталоги удалены,
порты 55432/3002 свободны. Рабочая БД не использовалась.

Для повторения нужен новый контейнер `rodovo-recovery-test` с меткой
`rodovo.task=recovery-drill`, PostgreSQL 16 на 127.0.0.1:55432, две пустые
БД с указанными выше именами, явные TEST_DATABASE_URL/RECOVERY_DATABASE_URL,
RODOVO_CI_DATABASE=disposable, RODOVO_RECOVERY_DRILL=disposable и
RECOVERY_CONTAINER=rodovo-recovery-test. DATABASE_URL переопределяется
недоступным тестовым адресом. Требуется готовая сборка и свободный порт 3002.
Команда сама не создаёт и не удаляет контейнер. Production RPO/RTO не измерены.
