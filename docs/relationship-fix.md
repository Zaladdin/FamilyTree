# Явные родственные связи

## Причина пропавшей связи с мамой

Добавление супруги к человеку, у которого уже есть дети, сохраняло только брак. Отдельная связь родитель → ребёнок не создавалась. Дерево показывало сохранённые данные правильно, но форма не позволяла указать общих детей или связать две уже существующие карточки.

## Поведение

- У выбранного человека с правом редактирования появилась кнопка «Добавить связь».
- Можно выбрать другую существующую карточку и явно указать, кем приходится выбранный человек: родителем, ребёнком или супругом. Перед сохранением показано направление связи; новая карточка не создаётся.
- Повторное сохранение той же связи не создаёт дубль, включая обратное направление записи супругов.
- При добавлении нового супруга или супруги можно отметить конкретных общих детей. Галочки по умолчанию выключены; смена родственника или вида связи сбрасывает выбор.
- Без отметки общих детей создание супруги не делает её родителем существующих детей.
- Прямое добавление «Родитель» относительно ребёнка продолжает создавать связь с этим ребёнком.

## Ограничения и сохранение

- Существующие карточки должны быть активными и принадлежать одной семье.
- Проверяются права редактирования, Origin, запрет связи с собой, циклы предков, несовместимые прямые связи и лимит двух различных родителей.
- Архивные связи учитываются в ограничениях, даже когда их нет на активной схеме.
- Снимок дерева, проверка, запись связи и журналирование выполняются в одной serializable-транзакции с ограниченными повторами при конфликте.
- Новая форма только добавляет связи. Удаление и замена ранее ошибочно указанных родителей в эту доработку не входят.
- Существующее автоматическое связывание нового ребёнка с единственным супругом выбранного родителя не изменено.

## Проверки

Автотесты используют синтетические семьи и изолированные заглушки хранилища: реальная БД не используется для тестовых мутаций. Проверяются добавление мамы после отца и ребёнка, вывод сохранённой линии на схеме, выбранные/невыбранные общие дети, направление связи, ошибки входных данных, дубли, права, циклы, ограничения родителей и конфликты транзакций.

- `npm test`: 133/133 прошли; TypeScript, ESLint и production-сборка проходят.
- Изолированная браузерная проверка реальных компонентов: 4 человека / 3 связи → добавление мамы к сыну → 4 человека / 4 связи; повтор не меняет количество. Создание супруги с одним отмеченным общим ребёнком добавляет ровно одну карточку и две связи. Выбор детей сбрасывается при смене вида родства.
- Для повторения UI-проверки: `npx tsx scripts/relationship-ui-preview.ts`, затем `http://127.0.0.1:3001/relationship-ui`. Только вымышленные данные в памяти; сервер не подключается к БД и не предоставляет настоящую авторизацию/API. Стенд не включён в маршруты приложения.
- После отдельного подтверждения пользователя в указанном дереве добавлена одна отсутствовавшая связь мать → сын через проверенный репозиторий. Существующие связи не изменены; действие записано в журнал. Никакие тестовые карточки в рабочей БД не создавались.
- Повторное чтение настоящего дерева подтвердило обоих родителей и линию мамы в общем виде; в режиме близких родственников ветвь ребёнка начинается от линии обоих родителей. Новый production API без входа возвращает 401, а запрос с чужим Origin — 403. Временный UI-стенд после проверки остановлен; основной сервер работает на порту 3000.
